# 計畫：v0.7.0 灰盒對手攻防（2026-09-23）

> 狀態：玩法與工程預設值已獲使用者確認，從 `v070-greybox-duel` 分支實作。已知良好狀態：`main 3eff8be`（v0.7.0 計畫文件；遊戲程式仍為 v0.6.2），線上 v0.6.2 為 `origin/gh-pages fcaf70c`（來源 `cdb41d0`）。每一步從已知良好提交建立可回退點。
>
> 目的：在既有 40m × 40m 練習場，加入可反覆開局的單人灰盒對手，讓玩家用移動、普攻和符印牆驗證追擊與閃避手感。本批是**手感驗證切片**；WebGL 互動通過不等於原生手機 10 人／10 分鐘驗收通過，也不解鎖 `ARCHITECTURE.md` 的後續階段。

## 1. 已確認的玩法

| 項目 | 本批規則 |
|---|---|
| 入口 | 保留木樁與原練習場。場邊放一名紅色灰盒對手；只有點選它才開始一局。待機時不追、不攻擊、不受傷。 |
| 對手 | 追近玩家，只有一招有明確地面預警的近距離攻擊；不施放元素、不新增技能樹、地形或多人功能。 |
| 玩家 | 對局中可點地移動、點對手普攻、使用既有微滑步與**玩家符印牆**。`WATER`／`FIRE`／`WIND`／`ELEM` 暫停使用；HUD 按鈕仍攔截觸控，不把按鈕點擊漏成移動。 |
| 血量與傷害 | 英雄 100 HP；對手 300 HP；對手命中英雄扣 20。英雄普攻沿用 `HeroTuning.asset` 的既有傷害與節奏，不為此批改值。既有破牆護盾先吸收對手傷害，溢出再扣英雄 HP。 |
| 預警 | 單招前搖 0.7 秒；鎖定前搖開始時英雄的位置，以高對比紅色地面圓圈表示命中區。結算瞬間英雄在圈外或被實體牆阻擋就不受傷；每次出手只結算一次。預警不與玩家原有的藍色瞄準預警共用狀態。 |
| 結束與再開 | 任一方 HP 歸零即結束本局，取消未結算攻擊與鎖定，雙方暫停 2.5 秒；然後回各自出生點、補滿血、清掉暫時戰鬥狀態，對手回待機。再點對手才開下一局。 |

### 實作前固定的工程預設值

使用者已確認 **100／300／20／0.7／2.5**，並於 2026-09-23 回覆「可以」核准其餘四值：對手移速 `4.0 m/s`、停止追擊距離 `1.8 m`、攻擊圈半徑 `1.5 m`、每次結算後 `1.0 s` 才可再起手。這些值集中放入一份 `DuelTuning`，測試另用獨立常值斷言防止調壞 tuning 後一起變綠；若手機試玩要調整，先更新本節與驗收用例，再改程式，不暗改門檻。

## 2. 邊界、接線與風險

1. **單一局面狀態**：`Dormant → Active → KnockoutPause → Dormant`。重複點擊待機對手只開一局；局中點它交給現有普攻路徑；倒地停頓期間忽略移動／攻擊／符印指令。對手在 `Dormant` 不可受玩家、砲台、元素或符印造成的傷害，且不會被其他系統誤當成活躍戰鬥目標。不要為此修改凍結的 `ICombatTarget`／`ISkillTelegraphService` 簽章。
2. **單一路由**：在延遲注入層 `heroInput` 之後放一個 `DuelInputRouter`，讓英雄與符印施放器只訂閱此路由，不再直接訂閱 `heroInput`。路由只透過注入的 `ICombatTarget` 對手參照與 Core 回合狀態判斷，不讓 `Vow.Input` 依賴 `Vow.Combat`。路由收到待機對手選取時只開局、**不轉發**當次普攻；Active 時才轉發一般移動／攻擊／微滑步／符印；KO 停頓時全部攔下。不能靠「先訂閱事件」消費 C# 多播事件。開局點擊仍經同一個 50／80 ms 延遲層；回合切換時要讓延遲層丟棄前一局尚未送出的指令，避免停頓尾端輸入在重置後意外開局，並限定此取消只用於回合切換，保留平時「保序、不丟」契約。進入 KO 時還要取消 `PlayerInputService` 仍在進行的符印手勢，免得重置後鬆手生成一筆新施放事件。
3. **雙方重置**：新增明確的「取消目前指令／動畫事件／目押緩衝並回 Idle」入口，處理英雄在 `AttackWindup`、`AttackRelease`、`CadenceDashing`、`AttackRecovery` 各狀態倒下。這是復活專用重置，不放寬 `PlayerStateMachine` 正常轉換表。傳送前停 NavMeshAgent 與移動；回出生點後重綁位置並恢復移動。破牆護盾、縛足／減速、符印施放冷卻、仍存活的玩家符印牆、尚未結束的符印手勢、延遲指令與攻擊預警都要清理，不能污染下一局；撤銷牆須走正常 `CollapseWall` 流程，還原 `BlockGrid` 與池名額。
4. **導航與牆**：對手與英雄共用 `BlockGrid` 障礙資料，卻各持有獨立 `GridNavigator`（其流向／快取是可變狀態）。沿用 `HeroLocomotion` 的 NavMeshAgent 手動位移與 SphereCast，不能開 `NavMeshObstacle.carving` 或執行期重烘。`Phase1Bootstrap.HandleNavBlockerStamped` 目前只推開英雄，本批要同一入口也檢查對手。符印牆要同時擋住追擊路徑與攻擊命中；命中遮擋只計算真正阻擋的牆，不能被木樁、對手自身或英雄的碰撞體誤擋。牆在對手腳下生成時，不可穿牆或永久卡住。
5. **元素與測試設施隔離**：開局時終止既有 `ElementZoneField` 區域並歸還視覺池，讓舊流沙／燃燒區不影響本局；對局與停頓時四顆元素鈕停用但仍吃觸控，回待機後恢復。砲台在開局時關閉，且**取消池內已飛出的子彈**；`TestTurret.SetFiring(false)` 本身不收回飛彈，不能只靠它。`TURRET`／`ENEMY WALL` 除錯鈕在對局與停頓時不能污染攻防測試。木樁、既有測試牆、原練習場非對局操作保持原行為。
6. **目標名冊**：新對手走 `CombatTargetBehaviour`，場景中預置 Collider 與 `TargetOverheadDisplay`。`ColliderTargetRegistry` 與 `CombatTargetRoster` 的成對登記不可拆散。待機時 `IsAlive` 保持 true，供 `PlayerInputService` 仍能選到；`CanBeTargetedBy` 則回 false，避免英雄普攻鎖定。因基底 `ReceiveDamage` 非虛擬，須在此唯一傷害入口增加預設允許、由對手覆寫的受傷閘，統一擋住待機的 AOE、砲台與普攻，不能在各傷害來源分別補丁。
7. **畫面**：場景建置器預置紅色對手與紅色預警，不在執行期 `CreatePrimitive`。用精簡 HP／局面提示顯示英雄當前 HP、對手 HP 與「點對手開始／對局中／重置中」；不再往已接近螢幕下緣的左側 HUD 加整列。手機橫式檢查文字、對手與木樁血條不重疊。

## 3. 實作順序與每步驗收

以下每步以**一個可審查提交／PR**為單位。相依順序 `A → B → C → D`；共用組裝根、場景與最終互動，無安全的平行寫入段。開工前先保存 `git status --short --branch` 與 `git rev-parse HEAD`；每一步驗收不過，就回到該步起點修正，不在壞掉的基線上疊下一步。

### A. 回合核心、血量與可復原的英雄狀態

**起始脈絡**：`Assets/Scripts/Core/Logic/HeroCombatBrain.cs` 持有鎖定、緩衝與時間；`PlayerStateMachine.cs` 的一般轉換表不能被死亡重置破壞。`HeroController.cs` 目前沒有 HP；`RockShieldLogic.Absorb()` 已有邏輯，但 `IRockShield`／`RockShieldBehaviour` 尚未對外提供受傷吸收入口。

**工作**：在 `Core/Logic` 建立單一 `DuelRoundLogic`／`DuelTuning`（名稱可依現有命名調整）與英雄生命邏輯；明確實作 `Dormant/Active/KnockoutPause`、一次性 KO 與 2.5 秒倒數。讓 `HeroController` 有受傷、HP 與復活專用重置；將護盾吸收接到受傷入口，清盾與停止移動接到復活；加入純邏輯測試與必要的 `IRockShield` 新方法，保留現有介面方法與 `ICombatTarget` 原樣。

**驗收**：獨立常值斷言 100 HP、300 HP、20 傷害、0.7 秒、2.5 秒（不可只把期望值讀自同一份 tuning）；英雄 100→80；有 15 盾時受 20 傷害只扣 5 HP；0 HP 只觸發一次 KO；2.5 秒前不能重開、期滿回待機且 HP 全滿；四種攻擊中間狀態復活後均無舊目標、舊指令或晚到的動畫命中。`PlayerStateMachine` 原轉換表逐值不變。跑 `bash Tools/DotnetCheck/verify.sh` 與 Unity EditMode；任何新測試須先證明錯誤行為會紅。

**回退**：回到 A 起點提交；不帶著半套生命入口做 B。

### B. 對手追擊、單招與牆判定

**起始脈絡**：`CombatTargetBehaviour` 負責目標 HP、死亡事件與顯影；`SkillTelegraphService` 可顯示獨立的 `ZoneCast`；`HeroLocomotion` 已有 NavMesh／格點繞牆與撞牆處理；`Phase1Bootstrap.BuildNavGrid` 持有全場唯一 `BlockGrid`。

**工作**：新增 `TrainingOpponent` 及獨立攻擊循環：待機無敵、Active 追近、到射程後停步並鎖定圓心、顯示 0.7 秒預警、單次命中判定、1.0 秒恢復。對手使用同一 `BlockGrid` 的另一個 `GridNavigator`；預警服務另建紅色實例；死亡時停止追擊、隱藏預警。場景建置器將對手置於 `(-4, 0, 8)` 附近，與 `(0, 0, 6)` 的木樁分開，並預置血條與材質；原 `(4, 0, 6)` 位置擋住 V4h 直線移動路線，`(-4, 0, 6)` 則截住砲台至木樁的 `z=6` 彈道，已依完整 PlayMode 的紅燈移出兩條路線，測試門檻不動。實際落點以不遮擋木樁點選與鏡頭可見為閘。本步即加入最小 `Phase1Bootstrap` 組裝與 `DuelInputRouter`，讓真實輸入可開局；完整清場、HUD 與兩局循環留給 C。

**驗收**：待機多次點擊僅開始一次，第一次點擊不讓英雄鎖定或打到對手；從無牆位置追近且只出一招；0.7 秒前英雄不扣血，剛過 0.7 秒才判定；英雄留在圈內受 20、走出圈外受 0，圈內／圈外邊界各測一個點；牆在中間受 0，撤牆後可命中；追擊能繞符印牆，不能穿過或卡住；對手不使用元素。待機可被點選但 HP、`OnDamaged` 次數與受擊顯影次數均不變。PlayMode 必須經真實 `PlayerInputService` 目標點選與動畫／時間路徑，不能只直接呼叫攻擊結算。跑 Unity EditMode／PlayMode 與 `verify.sh`。

**回退**：回到 B 起點；保留已通過的 A，不改 A 的驗收值來遷就場景。

### C. 組裝、輸入隔離與完整兩局循環

**起始脈絡**：`Phase1Bootstrap` 組裝延遲輸入、目標名冊、元素鈕、砲台和符印；`ElementField` 的區域邏輯與視覺池要一起清空；`DebugHud` 左側列數已接近小螢幕極限。

**工作**：擴充 B 的回合組裝與 `DuelInputRouter`，接上英雄生命、對手死亡事件、HP／局面顯示。開局時取消英雄原有木樁／牆目標、清理元素區域、盾、符印牆、砲台池內飛彈與預警；對局期間鎖元素及測試設施按鈕但保留觸控攔截；KO 停頓期間封住全部戰鬥輸入。回合邊界清空延遲層的未送出指令，進入 KO 時取消尚未放手的符印手勢。重置時雙方回出生點、滿血，木樁和原練習功能在非對局時可用。

**驗收**：以真實觸控路由完成「點紅對手→追擊／躲招→英雄普攻擊倒對手→停 2.5 秒→重置→再次點紅對手」；另走英雄被擊倒分支。第一下點選只開局，對手不掉血；第二下才可普攻。停頓前後各測一次極速立牆、滑步和破牆護盾；清牆後 BlockGrid 無鬼格、池槽位可再次借用；元素鈕不可施放且不可漏點，回待機可用；場上既有元素區域／已飛出的砲台子彈／開啟砲台均不讓待機或剛開局的對手掉血，開局前即將命中的飛彈取消後也不能消耗新牆血量。50／80 ms 延遲模式下開局只觸發一次；在 KO 停頓最後 80 ms 送 Target／Move／Flick／QuickCast／RuneReleased，重置後均不得生效；KO 前開始、重置後才鬆手的符印手勢也不得成牆。跑完整 EditMode／PlayMode、`verify.sh`、`mutation_check.py`；`ZeroAllocationTests` 量測窗口加入至少一輪追擊與出手的活性證明，既有 0 byte 與時間門檻不放寬。

**回退**：回到 C 起點；留下 A、B 可測的功能，不推送 WebGL。

### D. 視覺實測、文件與試玩版送達

**起始脈絡**：版本來源為 `Assets/Scripts/Core/VowVersion.cs` 與 `ProjectSettings/ProjectSettings.asset`；WebGL 部署由 `Tools/deploy-webgl.sh` 執行；上版送達證明見 `docs/HANDOFF.md` 與驗收指南 §16。

**驗收**：`verify.sh` 全綠、Unity EditMode／PlayMode 0 失敗、零配置測試 0 byte，WebGL 建置成功；線上實際點選、躲一次、吃一次、KO、2.5 秒後再開一局，console 0 error。讀回 `git log origin/gh-pages -1` 與線上版本列 `v0.7.0`，記錄來源 SHA、部署時間與互動畫面。原生手機 10 人手感測試若未做，明列未驗證。遇 PWA 舊版，告知關閉分頁重開或強制重新整理。

**回退**：保留 v0.6.2 的 `fcaf70c` 與來源 `cdb41d0` 作為可回退送達點；D 不通過就不宣稱 v0.7.0 已送達。

## 4. 變更規則與回報

- §1 使用者已確認的玩法與數值，以及 §3 的驗收案例一旦開始實作即凍結；若要放寬門檻或改預期，先指出原條件何處有錯並取得使用者裁定。只加嚴與修正錯字可記錄後繼續。

- 每步回報：起點與終點 SHA、改動檔案與行號、實跑指令及**實際輸出**、未驗證項、可回退點。最終送達另附 `origin/gh-pages` 與線上版本列證明。
