推導出的性質（實作不得打破；打破就是改了暫定值，要走 §4）：
1. 1.5 < 2.5：英雄從塔心躲開攻擊圈後，仍可能留在光圈內，引導不會因為躲招而中斷。
2. 2r＝5.0 ≤ 6.0：英雄站在對手所在光圈的任何位置，對手都會轉頭追打。
3. 英雄射程 5.0 < 6.0：英雄每次打中對手時，對手一定已進入追打狀態，不會出現「英雄在觸發距離外偷打」。
4. 7.12 > 6.0：雙方各自在相鄰兩塊引導時，不會觸發追打。
5. 10.0 − 6.0 = 4.0 的遲滯；英雄比對手快 1.5 m/s，所以可以甩掉對手。
6. 0.7 < 1.5 < 2.5：復活時站在自家光圈內，且不會和站在塔心的敵人身體重疊。
7. 18.1875 < 19.0 < 19.45 < 20：板塊全部在場內並留邊。

## 3. 實作順序與每步驗收

順序 `A → B → C → D`，每步一個可審查的提交。四步共用組裝根、場景與最終互動，沒有可以安全並行寫檔的區段。開工前保存 `git status --short --branch` 與 `git rev-parse HEAD` 的輸出。任一步沒過，就回到該步起點修，不在壞掉的基線上疊下一步。

**所有 V 條文共同遵守：**
- 期望值一律寫成字面值，**不得讀受測的 `CaptureTuning`／`HexBoardLayout` 欄位**來算期望值（否則把數值改壞，測試會跟著一起變綠）。
- 純邏輯時序一律用 dt＝0.25（必要時 0.125），都是二進位有限小數，tick 數才精確。
